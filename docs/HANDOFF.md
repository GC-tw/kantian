## 5. 檔案結構
- `data/mountains.json`：235 座山，是網頁實際使用的資料。
  - 欄位：`c` 類別、`no` 編號、`n` 顯示名稱、`h` 標高、`pid` 氣象署登山預報點代碼、`pt` 預報點名稱、`co` 縣市（多個以「、」分隔）、`tw` 鄉鎮清單、`note` 備註、`cn` 氣象署原始名稱（用來比對）、`al` 別名陣列。
- `data/mountains_235.csv`：同一份資料的試算表版，最後一欄是「別名」。
  - UTF-8 with BOM、CRLF 換行，修改時要保持這個格式。
  - 也同步存在 claude.ai 專案文件 `claude/mountains_235.csv`。每次修改 CSV 後，用 Projects 工具的 `project_write` 搭配 `local_path` 更新。
- `data/datasets.json`：自動探查到的登山預報資料集代碼。刪除這個檔案，下次執行就會重新探查。
- `data/stations.json`：151 個登山預報點的經緯度，用來核對縣市。
- `data/last-run.json`：最近一次執行是否成功、失敗原因、警告、摘要（含一週天氣描述統計）。
- `data/wx-log.json`：天氣用語紀錄（2026-10-19 新增，只紀錄、不影響燈號）。
  - `terms`：每個出現過的天氣描述，累計次數、首次與最後出現日期、出現時有效的特報種類。
  - `runs`：最近 120 次執行（約 30 天）各自的用語統計與有效特報。
  - `watch`：含「大雨、豪雨、霧、雪、冰、雷」的用語。
- `data/samples/`：各資料集的格式樣本。
- `scripts/fetch.mjs`：抓氣象署資料，輸出 `dist/forecast.json`。Node 22 以上，不需要安裝任何套件。
- `scripts/build.mjs`：把 `site/template.html`、`site/app.js` 和山岳資料組成 `dist/index.html`。
- `site/app.js`：網頁程式。`site/template.html`：版面、樣式、「排序規則與說明」頁的文字。
- `site/icons/`：圖示（`icon.svg`、favicon、App 圖示 PNG、maskable）與 `manifest.webmanifest`，`build.mjs` 會複製到 `dist/`。PNG 由 SVG 用 playwright 截圖產生。
- `test/package.json`、`test/package-lock.json`：完整測試安裝 jsdom 時自動產生，已列入 `.gitignore`。
- `.github/workflows/update.yml`：自動排程與部署。
- `test/quick.mjs`：快速檢查。`test/page.test.js`：完整測試（jsdom）。`test/make_fixtures.py`：產生測試用的假資料。

- **鄉鎮預報：** 各縣市資料集 F-D0047-001～087。
  - n 為 3 天逐 3 小時，n+2 為一週；例如 001／003 是宜蘭縣。
  - 089／091 只到縣市層級，不要用。
- **天氣警特報：** W-C0033-001。時間字串沒有標時區，一律當台灣時間解讀。

- **一週預報的降雨機率只有前 3 天**（6 個時段）有值，第 4 天起是「-」。
- **天氣描述的實際用語**（2026-10-19 全臺統計）：陰陣雨、陰短暫陣雨、多雲短暫陣雨、晴時多雲等。
  - 很少或沒有出現「大雨、豪雨」，雨量大小主要靠降雨機率和特報判斷。
  - 待觀察：颱風或豪雨期間的用語（霧、雪規則已於 2026-10-19 決定，見 §7）。
- **官方天氣描述代碼表**（https://www.cwa.gov.tw/V8/assets/pdf/Weather_Icon.pdf，代碼 1–42）：
  - 沒有「大雨」「豪雨」這類雨量強度用語，所以 `judge()` 的「描述有大雨、豪雨」規則實際上不會觸發，雨量大小只能靠降雨機率和特報。
  - 霧：代碼 24–28、31–32、35–41（如「晴有霧」「多雲有霧」「有霧有陣雨」）。
  - 雪：代碼 23、37、42（「雨或雪」「下雪、積冰、暴風雪」）。
  - 資料裡的 `WeatherCode` 有這個代碼，目前程式只用文字 `Weather`。

## 7. 燈號規則（`site/app.js` 的 `judge()`，要和「排序規則與說明」頁一致）
- **燈號名稱（2026-10-20 使用者決定）：** A（適合）、B（注意）、C（不建議），格子內直接寫字母。下面規則中的「適合／注意／不建議」即 A／B／C。
- **A+：** A 之中天氣描述剛好是「晴」（使用者選最嚴格，「晴時多雲」不算）。實心綠色、寫「A+」，class 為 `lamp g p`。
  - 一週模式：登頂時段對應的所有半天都是「晴」才算（`dayForecast` 的 `sunny`）。
  - 跨鄉鎮的山：每個鄉鎮都是 A+ 才算。
- **降雨：**
  - 降雨機率 <30% 適合；30% 以上注意；60% 以上不建議。
  - 天氣描述有「大雨」「豪雨」：不建議。
- **第 4–7 天沒有降雨機率：**
  - 描述有「雨」判注意，理由寫原始描述加「（第 4–7 天無降雨機率）」。
  - 「陣雨」（不含「短暫」）標記為 heavy，只影響排序，不升級成不建議（使用者已確認）。
- **雷：** 描述有「雷」，不建議。
- **霧：** 描述有「霧」，注意（2026-10-19 使用者決定）。
- **雪：** 描述有「下雪」「積冰」「暴風雪」，不建議；其他有「雪」的描述（如「雨或雪」），注意（2026-10-19 使用者決定）。
- **風速（平均風速）：** <8 m/s 適合；8.0–13.8 注意；13.9 以上不建議。
- **高溫：** 只看標高 1,000 m 以下的山，體感溫度 ≥36°C 為注意。
- **低溫：** 不列入燈號（靠裝備應對）；低溫特報為注意。
- **特報：** 颱風、豪雨、大雨、陸上強風，不建議；低溫、濃霧，注意。
- **取最差：** 各項取最差的結果；跨多個鄉鎮的山取最差的鄉鎮。

## 9. 修改與部署流程（重要，影響速度）
- **只改網頁**（`site/**`、`scripts/build.mjs`）：
  1. 跑 `node test/quick.mjs`，只要幾秒。
  2. commit 後 push 到 main。
  3. GitHub Actions 自動部署，沿用網站上最新的天氣資料（9 小時內），約 20 秒。
- **改到燈號、排序、資料處理：**
  1. 先跑完整測試：
     ```
     python3 test/make_fixtures.py
     TZ=Asia/Taipei node scripts/fetch.mjs --fixtures test/fixtures --out dist/forecast.json
     node scripts/build.mjs
     cd test && npm i jsdom@24.1.3 && TZ=Asia/Taipei node page.test.js
     ```
     完整測試約 1–2 分鐘，加 `timeout` 避免卡住。
  2. 再 push。
- **改到 `data/mountains.json` 或 `scripts/fetch.mjs`：**
